# Contract: segment DSL

Status: v1 · 2026-11-08 · owner: orchestrator · implements: R-FLOW-1, R-AUD-1, R-AUD-2, R-AI-1

The LLM proposes an audience as a **rule** in this DSL. The backend validates it and compiles it to
parameterized SQL through a whitelist. Nothing the model writes is ever executed as SQL.

Single source of truth in code: `internal/catalog` (fields, operators, limits). The prompt text, the wire
schema (`segment.wire.schema.json`, generated by `make schema`), the validator, the SQL compiler and the UI
labels (`GET /api/catalog`) are all derived from it.

## 1. Shape (CNF, fixed depth)

```json
{
  "segment": {
    "groups": [
      { "conditions": [ { "field": "city", "op": "eq", "value": "İstanbul" } ] },
      { "conditions": [ { "field": "last_cart_add_at", "op": "within_last_days", "value": 30 } ] }
    ]
  },
  "unsupported_criteria": ["likes football"],
  "assumptions": ["'alışveriş yapmayan' read as: no purchase since the cart add"],
  "channels_requested": "both",
  "language": "tr",
  "explanation": "İstanbul users who added to cart in the last 30 days and have not purchased since."
}
```

- `groups` are **ANDed**; the `conditions` inside one group are **ORed**.
- Zero groups means "all users" (consent still applies). The validator adds the warning `targets_everyone`.
- Every condition has exactly `field`, `op`, `value`. Operators without an operand take `"value": null`.
- `unsupported_criteria[]`: parts of the brief we have no data for. Shown to the user; never turned into fields.
- `assumptions[]`: interpretations the model made. Shown to the user.
- `channels_requested`: `sms` | `email` | `both` (`both` when the brief does not say).
- `language`: `tr` | `en`, the language of the brief.
- `explanation`: secondary text. The UI's primary display is the server rendering (§6).
- **Consent is not a field.** The model cannot target or untarget consent; the system enforces it (R-AUD-2).

## 2. Fields

All columns are on `users u`. Dates are `timestamptz`; NULL means "never happened".

| Field | Type | SQL expression | Range / values |
|---|---|---|---|
| `city` | enum | `u.city` | İstanbul, Ankara, İzmir, Bursa, Antalya, Adana, Konya, Gaziantep, Kocaeli, Eskişehir, Trabzon, Kayseri |
| `locale` | enum | `u.locale` | tr, en |
| `age` | number (integer) | `EXTRACT(YEAR FROM age(u.birth_date))::int` | 18..100 |
| `loyalty_tier` | enum | `u.loyalty_tier` | bronze, silver, gold, platinum |
| `favorite_category` | enum (nullable) | `u.favorite_category` | electronics, fashion, home, beauty, sports, books, grocery, toys |
| `signup_at` | date | `u.signup_at` | — |
| `last_login_at` | date (nullable) | `u.last_login_at` | — |
| `last_purchase_at` | date (nullable) | `u.last_purchase_at` | — |
| `last_cart_add_at` | date (nullable) | `u.last_cart_add_at` | — |
| `purchase_count` | number (integer) | `u.purchase_count` | 0..100000 |
| `total_spent` | number (TRY) | `u.total_spent` | 0..10000000 |
| `cart_abandoned` | bool | `u.cart_abandoned` | generated: cart add exists and no purchase since |

Enum values are matched **exactly** (case and diacritics). `istanbul` is an error `invalid_enum_value` whose
message lists the allowed values; the repair loop fixes it. The backend never silently normalizes values.

## 3. Operators and SQL

`$n` is always a bind parameter. No value is ever concatenated into SQL.

| Type | Op | Value | SQL |
|---|---|---|---|
| number | `eq` `neq` `gt` `gte` `lt` `lte` | number | `expr = $n` · `<>` · `>` · `>=` · `<` · `<=` |
| number | `between` | `[lo, hi]`, lo ≤ hi | `expr BETWEEN $a AND $b` (inclusive) |
| enum | `eq` `neq` | string | `expr = $n` · `expr <> $n` |
| enum | `in` `not_in` | non-empty string list | `expr = ANY($n)` · `expr <> ALL($n)` |
| bool | `is_true` `is_false` | `null` | `expr IS TRUE` · `expr IS FALSE` |
| date | `within_last_days` | integer days | `expr >= now() - make_interval(days => $n)` |
| date | `not_within_last_days` | integer days | `(expr IS NULL OR expr < now() - make_interval(days => $n))` |
| date | `before` | `YYYY-MM-DD` | `expr < ($n::date)::timestamp AT TIME ZONE 'Europe/Istanbul'` |
| date | `after` | `YYYY-MM-DD` | `expr >= ($n::date + 1)::timestamp AT TIME ZONE 'Europe/Istanbul'` |
| date | `is_null` `is_not_null` | `null` | `expr IS NULL` · `expr IS NOT NULL` |

Relative time always uses the `*_days` operators, so the model never computes absolute dates.

**NULL semantics** (tested):

- `not_within_last_days N` includes NULL: "has not purchased in 30 days" includes "never purchased".
- Every other comparison on NULL is false (SQL three-valued logic; `neq` and `not_in` also exclude NULL).

## 4. Limits (validator only; the wire schema cannot express them)

| Limit | Value | Error code |
|---|---|---|
| Groups | ≤ 5 | `too_many_groups` |
| Conditions per group | 1..10 | `empty_group`, `too_many_conditions` |
| Conditions in total | ≤ 20 | `too_many_conditions` |
| `in` / `not_in` list | 1..50 items, no duplicates | `empty_list`, `list_too_long`, `duplicate_value` |
| Days | integer 1..3650 | `out_of_range`, `not_integer` |
| Numbers | within the field's range; integer fields need integers | `out_of_range`, `not_integer` |
| Dates | valid `YYYY-MM-DD` between 2000-01-01 and 2100-12-31 | `invalid_value` |
| Strings | ≤ 100 runes | `string_too_long` |
| `unsupported_criteria`, `assumptions` | ≤ 10 items, each ≤ 300 runes | `list_too_long`, `string_too_long` |
| `explanation` | ≤ 1000 runes | `string_too_long` |

## 5. Validation pipeline and errors

1. **Stop reason.** `refusal` → shown to the user, no repair. `max_tokens` → invalid, one repair with a larger limit.
2. **Strict decode.** `DisallowUnknownFields`, no trailing data: `invalid_json`, `unknown_property`,
   `missing_property`, `wrong_type`.
3. **Structural.** `unknown_field`, `unknown_operator`, `op_type_mismatch`, `invalid_enum_value`.
4. **Semantic.** Limits above; `contradiction` (error); `duplicate_condition` (warning); `targets_everyone` (warning).
   A contradiction is reported only when provable without data (need.md N-ORC-004): two single-condition
   groups on the same field whose ranges cannot overlap, or `is_null` with a value comparison on the same field.
5. **Compile.** Only `segment.ValidRule` compiles; only `segment.Validate` constructs one.
6. **Dry-run count** with `statement_timeout`: `total`, `sms_reachable`, `email_reachable`, `both`.

Errors are structured; `path` is a JSON path into the proposal:

```json
[{ "path": "segment.groups[1].conditions[0].value", "code": "invalid_enum_value",
   "message": "city must be one of: İstanbul, Ankara, …" }]
```

Repair loop: on errors, the errors are sent back to the model as a follow-up turn, at most **2** repairs, each
recorded in `llm_calls` with purpose `repair`. Still invalid → HTTP 422 with the errors. Rules are never relaxed.

## 6. Server rendering (what the UI shows as primary)

`segment.Render(rule, locale)` returns one entry per group; conditions joined by "or" / "veya", groups by
"and" / "ve". Examples (en / tr):

| Condition | en | tr |
|---|---|---|
| `city eq İstanbul` | City is İstanbul | Şehir: İstanbul |
| `last_cart_add_at within_last_days 30` | Added to cart in the last 30 days | Son 30 günde sepete ürün ekledi |
| `cart_abandoned is_true` | Has an abandoned cart | Sepeti terk edilmiş |
| `last_purchase_at not_within_last_days 30` | No purchase in the last 30 days (incl. never) | Son 30 günde alışveriş yapmadı (hiç yapmamış dahil) |

## 7. Golden rule for the official brief (N-PLAN-011, reading A)

Brief: "Son 30 günde sepetine ürün ekleyip alışveriş yapmayan İstanbul'daki kullanıcılara %30 indirim
hatırlatması gönder. Samimi ama kısa olsun."

```json
{ "groups": [
  { "conditions": [ { "field": "city", "op": "eq", "value": "İstanbul" } ] },
  { "conditions": [ { "field": "last_cart_add_at", "op": "within_last_days", "value": 30 } ] },
  { "conditions": [ { "field": "cart_abandoned", "op": "is_true", "value": null } ] }
] }
```

`channels_requested: both`, `language: tr`. `assumptions` must mention the other reading ("no purchase in the
last 30 days"). Eval equivalence is measured on the resulting user-id sets, not on JSON shape (KICKOFF §6.11).

## 8. Wire schema (structured outputs)

`segment.wire.schema.json` is generated from the catalog. Conditions are an `anyOf` of typed variants, each
restricting `field` and `op` to a compatible set (need.md N-ORC-003):

| Variant | `field` | `op` | `value` |
|---|---|---|---|
| `number_compare` | number fields | eq, neq, gt, gte, lt, lte | number |
| `number_between` | number fields | between | array of number |
| `enum_compare` | enum fields | eq, neq | string |
| `enum_list` | enum fields | in, not_in | array of string |
| `bool_check` | bool fields | is_true, is_false | null |
| `date_relative` | date fields | within_last_days, not_within_last_days | integer |
| `date_absolute` | date fields | before, after | string, `format: date` |
| `date_null` | date fields | is_null, is_not_null | null |

Only keywords supported by structured outputs are used: types incl. `null`, `enum`, `anyOf`, `$ref`/`$defs`,
`format`, `required`, `additionalProperties: false`. A unit test rejects anything else and checks that the
committed file matches the generator.
